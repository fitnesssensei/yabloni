# 🌳 Яблони и Груши - Интернет-магазин саженцев

Django-based e-commerce платформа для продажи саженцев плодовых деревьев (яблонь и груш) с полным функционалом интернет-магазина.

## 📋 Обзор проекта

Проект представляет собой современный интернет-магазин с каталогом товаров, корзиной покупок, системой заказов и блогом. Разработан с использованием фреймворка Django 5.2.7 с адаптивным дизайном на Bootstrap 5.

### Шаги установки

1. **Клонирование репозитория**

   ```bash
   git clone <repository-url>
   cd yabloni
   ```

2. **Создание и активация виртуального окружения**

   ```bash
   python -m venv venv
   # Для macOS/Linux:
   source venv/bin/activate
   # Для Windows:
   venv\Scripts\activate
   ```

3. **Установка зависимостей**

   ```bash
   pip install -r requirements.txt
   ```

4. **Настройка базы данных PostgreSQL**

   ```bash
   # Создание базы данных
   createdb yabloni_db
   ```

5. **Настройка переменных окружения**
   Создайте файл `.env` в корне проекта:

   ```env
   # Настройки базы данных
   DB_NAME=yabloni_db
   DB_USER=your_username
   DB_PASSWORD=your_password
   DB_HOST=localhost
   DB_PORT=5432
   
   # Настройки email (Gmail)
   EMAIL_HOST=smtp.gmail.com
   EMAIL_PORT=587
   EMAIL_USE_TLS=True
   EMAIL_HOST_USER=your@gmail.com
   EMAIL_HOST_PASSWORD=your_app_password
   DEFAULT_FROM_EMAIL=your@gmail.com
   ```

6. **Миграции базы данных**

   ```bash
   python manage.py makemigrations
   python manage.py migrate
   ```

7. **Сбор статических файлов**

   ```bash
   python manage.py collectstatic --noinput
   ```

8. **Создание суперпользователя**

   ```bash
   python manage.py createsuperuser
   ```

9. **Запуск сервера разработки**

   ```bash
   python manage.py runserver
   ```

10. **Проверка установки**
    - Откройте http://127.0.0.1:8000/ в браузере
    - Админ-панель: http://127.0.0.1:8000/admin/

## 📧 Email-настройки

Проект использует Yandex SMTP для отправки уведомлений при оформлении заказов. Настройки email управляются через админ-панель Django и используются кодом напрямую из базы данных (модель `EmailSettings`).

### Важное обновление (февраль 2026)

Код в `orders/views.py` был обновлен для использования настроек email непосредственно из админки (`EmailSettings.load()`) и настроек инструкций заказов (`OrderInstructionsSettings.load()`), а не из файла `.env`. Это обеспечивает, что изменения в админке применяются сразу без необходимости перезапуска сервера.

**Дополнительное улучшение:** Настройки инструкций заказов выделены в отдельную модель `OrderInstructionsSettings` для удобства управления через админку. Код создает собственное SMTP-соединение с настройками из базы данных, используя `get_connection()`, что позволяет безопасно удалить или закомментировать email-настройки в `.env` файле.

### Создание пароля приложения Yandex

**Важно:** Используйте только пароль приложения, а не пароль от почты!

### Управление email-настройками через админку

Теперь все настройки email можно изменять прямо через админ-панель Django без редактирования файлов:

1. Перейдите в админку: `/admin/core/emailsettings/`
2. Отредактируйте настройки:
   - **Включить отправку email** — вкл/выкл отправки уведомлений
   - **SMTP сервер** — адрес сервера (smtp.yandex.ru, smtp.gmail.com)
   - **Порт SMTP** — обычно 465 для SSL или 587 для TLS
   - **SSL/TLS** — включить соответствующее шифрование
   - **Email отправителя** — полный адрес (например: shop@yandex.ru)
   - **Пароль приложения** — пароль для приложения (не от почты!)
   - **Email "От кого"** — адрес для поля From (если пусто — используется Email отправителя)
   - **Префикс темы** — префикс в теме всех писем
3. Сохраните — настройки применяются мгновенно!

**Тестирование из админки:**

- В списке настроек выберите запись
- В выпадающем меню "Действия" выберите **"Отправить тестовое письмо"**
- Нажмите "Выполнить" — письмо отправится на email отправителя

### Исправление проблем с HTTPS в разработке

Если при запуске dev-сервера (`python manage.py runserver`) возникают ошибки типа "Bad request version" или "You're accessing the development server over HTTPS, but it only supports HTTP", это связано с включенными настройками безопасности для продакшена.

**Решение**: Настройки безопасности HTTPS теперь условны и активны только при `DEBUG = False`:

```python
SECURE_SSL_REDIRECT = not DEBUG      # Перенаправление HTTP на HTTPS только в продакшене
SESSION_COOKIE_SECURE = not DEBUG    # Куки сессий только по HTTPS
CSRF_COOKIE_SECURE = not DEBUG       # Куки CSRF только по HTTPS
```

Эти изменения автоматически применяются в `settings.py`. Для разработки сервер работает по HTTP без проблем, а в продакшене настройки включаются автоматически.

### 📱 Мобильная версия галереи: лента больших фото со свайпом (Сентябрь 2026)

> ⚠️ **Вариант отменён** — см. ниже «📱 Фото на телефоне: сетка по 2 в ряд без главного фото (Сентябрь 2026)». Причина: в свайп-ленте на телефоне было видно только первое фото, и казалось, что фото у товара одно. Ниже описание оставлено для истории.

- **Что сделано**: на телефоне (< 768 px) миниатюр нет вообще — вместо них **лента больших фото**: одно фото на всю ширину, листается свайпом вбок с магнитной остановкой по центру (нативный скролл, JS-карусель не нужна).
- **Высота галереи**: ≈ 350 px вместо ≈ 650 px — почти пол-экрана экономии.
- **Файлы и правки**:
  - `config/settings.py` — новый размер в `THUMBNAIL_ALIASES`: `product_mobile` (600×600, quality 85). Телефону отдаётся крупная версия, десктопу — прежняя лёгкая миниатюра 150 px.

- **При деплое**: файлы 600×600 создаются автоматически при первом открытии страницы товара — нужны права на запись в папку `media/`. Никаких команд запускать не нужно.
- **Как проверить**: сузить окно браузера уже 768 px, либо в Chrome `⌥ + ⌘ + I` → `⇧ + ⌘ + M` (режим устройства) → ширина **767** = лента, **768** = десктопная сетка. После деплоя не забыть жёсткое обновление (Cmd + Shift + R), иначе возьмётся старый `style.css` из кэша.

### 🗄️ Локальная база данных: ошибка `database "yabloni_db" does not exist` (Сентябрь 2026)

- **Причина**: на компьютере не существовало самой базы `yabloni_db` (в `.env` она указана как `DB_NAME`). Django базу данных не создаёт — её нужно создать один раз вручную.
- **Решение**:

  ```bash
  cd yabloni2
  source venv/bin/activate
  createdb yabloni_db               # создать базу данных
  python manage.py migrate          # создать таблицы (всего 29 таблиц)
  python manage.py createsuperuser  # чтобы войти в /admin/
  ```

- **Проверка**: `python manage.py runserver` → `/` = 200, `/catalog/` = 200, `/nursery/` = 200, `/admin/` = 302 (редирект на форму входа — это норма, админка всегда требует логин).
- **Частая путаница**: если браузер при запуске сервера открывает `/admin/`, это автодополнение адресной строки (последний посещённый адрес сайта), а не редирект самого сайта — главная `/` отдаёт магазин (проверено заголовками: `200 OK`, заголовка `Location` нет; `Location` есть только у `/admin/`).
- **Важно**: локальная база пустая (0 категорий/товаров/новостей) и папка `media/` пустая (она в `.gitignore`), поэтому фото товаров локально появиться не могут. Варианты: создать товары заново в админке или перенести данные с боевого сервера (`pg_dump yabloni_db > dump.sql` на сервере → `psql -d yabloni_db < dump.sql` локально, плюс перенести папку `media/`).

### 📱 Фото на телефоне: сетка по 2 в ряд без главного фото (Сентябрь 2026)

- **Было**: на телефоне (< 768 px) вместо миниатюр показывалась свайп-лента крупных фото, но фактически было видно только первое фото — казалось, что у товара всего одно фото.

Горизонтальной прокрутки нет ни на одной ширине. Образцы фото взяты с боевого сайта только для показа — боевые база данных и папка `media/` не менялись.
